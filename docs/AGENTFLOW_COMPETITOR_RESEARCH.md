# AI workforce product benchmarks

Research date 23 November 2026. The environment’s network proxy returned HTTP 403 for the product sites. Public GitHub material was reachable. The sources below identify the revisions actually inspected. UI observations come from public instructional screenshots or explicit steps in documentation. No authenticated competitor accounts, live billing panels, private dashboards or competitor mobile sessions were examined. Samples establish that a pattern can be built; they do not establish default availability, plan coverage or generally available release status.

## Evidence and design implications

**Salesforce Agentforce.** The Trailhead recipes define a subagent’s eligible actions and inputs, and show a guaranteed sequence for dependent actions. Salesforce AI Research’s lifecycle example connects a safety gate, activation, preview/batch evaluation and trace analysis. A workflow author can specify which action follows a successful lookup instead of trusting the model to invent an order. For AgentFlow, keep the ordinary owner's role description editable; keep action contracts and permission checks on the server. Save a failed conversation as a candidate test case before changing a published version. The sample development toolchain is evidence about lifecycle design, not the native admin dashboard. [Recipes](https://github.com/trailheadapps/agent-script-recipes/tree/80b2eb37bb81f23143001425a618bc8416efec3d) · [Lifecycle](https://github.com/SalesforceAIResearch/agentforce-adlc/tree/09bf1539d41f9ff355ba3eb5d05d4a75813423bb)

**Relevance AI.** The public Gmail Manager screenshot shows a persistent agent identity, a focused core-instructions editor, and separate destinations for flow, tools, subagents, templates and task views. Its example instruction defines the task, response format and exclusions. The SDK exposes subagents and task execution; its approval example approves a task or a particular tool. An owner can understand an employee’s remit independently of its technical resources. Adapt this separation in AgentFlow. Keep tool-specific authority in the executor and require a visible assignee for human work. The screenshot is a product example; its navigation may have changed. [Interface](https://github.com/RelevanceAI/relevanceai/blob/af61c229bd171bf8ee78f856a4ebe9309435f034/assets/images/core_instructions.png) · [Agent operations](https://github.com/RelevanceAI/relevanceai/blob/af61c229bd171bf8ee78f856a4ebe9309435f034/relevanceai/resources/agent.py) · [Approval example](https://github.com/RelevanceAI/relevanceai/blob/af61c229bd171bf8ee78f856a4ebe9309435f034/examples/approve_tasks_in_bulk.py)

**Lindy.** The Home guide puts conversation and recent activity together. Empty cards stay hidden or explain what will populate them. Teach a Task walks a user from a recorded example through review. Team setup separates the administrator’s invitation from the recipient’s connection steps. Credentials have names, scope and replacement controls. AgentFlow can begin with a real customer question, distinguish unfinished setup from an empty queue, and make each workspace connection’s owner visible. Screen recording and personal calendar access would add permissions outside the immediate need. [Home and task guides](https://github.com/lindy-ai/docs/tree/cdaf692483e372a04273a0f3d3692e67b29eab0b/teammate) · [Team setup](https://github.com/lindy-ai/docs/blob/cdaf692483e372a04273a0f3d3692e67b29eab0b/start-here/team-setup.mdx) · [Credentials](https://github.com/lindy-ai/docs/blob/cdaf692483e372a04273a0f3d3692e67b29eab0b/integrations/credentials.mdx)

**Microsoft Copilot Studio.** The training screenshot shows global navigation, an environment indicator, agent-level destinations, a model selector, an instructions card and a test pane with its own message history. Publish is a separate action. The Academy’s newer experience walkthrough explicitly asks the learner to check the environment before creating assets. Its human-handoff lesson describes passing conversation context to a human. AgentFlow should keep the workspace, assistant and tested version legible across edits. On narrow screens, retain the selected conversation when switching back to configuration. Preview training material can differ from deployed versions. [Test pane](https://github.com/microsoft/agent-academy/blob/0726a031369829ebc22938207cc04bab7819c6d8/docs/special-ops/yaml-specialist/assets/test-agent.png) · [Environment selection](https://github.com/microsoft/agent-academy/tree/0726a031369829ebc22938207cc04bab7819c6d8/docs/operative-nextgen/01-get-started) · [Handoff lesson](https://github.com/microsoft/agent-academy/tree/0726a031369829ebc22938207cc04bab7819c6d8/docs/commander-preview/09-handoff-to-human)

**ServiceNow AI Agents.** A public practitioner lab for the Zurich release follows an incident through structured diagnosis, knowledge lookup, cooperating agents and remediation. The lab’s workflow wizard goes from Create and manage to adding participating agents, selecting a run-as identity, adding triggers and choosing channels/status. Its first-responder exercise lets an author add tools manually. An incident record provides continuity across those transitions. AgentFlow can use a conversation and its assignment history in the same way, while retaining explicit human authority for real bookings and payments. This is a secondary, release-specific source. Current native AI Agent Studio screens, licensing and defaults could not be verified. ServiceNow’s open-source AgentLab is a separate research project and was excluded as evidence about the commercial product. [Lab](https://github.com/raadlakha/AILab2.0/tree/ece1dd2c87989acb33a176fddd396e58fa9a2353) · [Product reference](https://www.servicenow.com/products/ai-agents.html)

**Dify.** Included for its knowledge and provider administration. A builder can test a query against a knowledge base, inspect the returned passages and tune retrieval before publishing. Operators can inspect individual app conversations and workflow runs. Workspace owners/admins can manage provider credentials, use platform credits or connect a provider account, and choose defaults. These are separate decisions for AgentFlow: paying for a model, making it eligible, choosing it for a version, and supplying authorized facts. [Retrieval](https://github.com/langgenius/dify-docs/blob/797c14989d2fe5cbed3edb2486fc13cf8de4e22a/en/cloud/use-dify/knowledge-base/test-and-tune.mdx) · [Logs](https://github.com/langgenius/dify-docs/blob/797c14989d2fe5cbed3edb2486fc13cf8de4e22a/en/cloud/use-dify/monitor/logs.mdx) · [Workspace and providers](https://github.com/langgenius/dify-docs/tree/797c14989d2fe5cbed3edb2486fc13cf8de4e22a/en/cloud/use-dify/workspace)

## Hostinger and n8n workflow follow-up

Reviewed 24 November 2026. Hostinger’s public Horizons page was blocked by the environment proxy. The evidence below comes from official repositories; it covers documented workflows. No Hostinger account, hPanel/Horizons session, n8n Cloud account, hosting purchase or deployment was used.

| Source | What the operator actually does | AgentFlow decision |
|---|---|---|
| Hostinger CLI | Check the active credential with auth status. Run a deployment dry run to inspect the resolved website, source and file scope before applying changes. Preview, reachable and deployed are distinct states. | Name the workspace, version and selected model in the playground. Show the inputs actually sent during a test. Treat public channel verification and in-app publication as separate milestones. |
| Hostinger’s n8n integration | Create a credential, choose the resource operation, enter its required inputs and execute the workflow. Credential testing is a separate operation. | In the channel roadmap, separate connection verification from assigning an assistant and enabling a customer-facing operation. Adopt the sequence only when each server-side check works. |
| n8n execution debugging | Open a recorded execution to inspect it. During development, pin or mock data to repeat tests against the same inputs. Production execution has different data semantics. | Attach inspection to an individual test reply. Resolve the recorded source selection against that thread’s saved configuration version. Do not rerun a model or trigger a business action simply to inspect a prior turn. |
